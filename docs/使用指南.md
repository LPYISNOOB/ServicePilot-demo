# ServicePilot 使用指南

本文面向第一次运行项目的人。默认流程不需要 API Key，不会消耗模型 Token。

## 1. 环境要求

- Windows 10/11 与 PowerShell 5.1 或 PowerShell 7
- Miniconda 环境：`langchain`
- Python 3.13（当前环境实测 3.13.5）
- Node.js 24 与 npm 11（当前本机已安装）
- Docker Desktop 可选，只在容器部署时使用

项目绝对路径：`D:\ServicePilot`。

## 2. 一键安装

```powershell
Set-Location D:\ServicePilot
.\scripts\setup.ps1
```

脚本会使用 `$env:USERPROFILE\miniconda3\envs\langchain\python.exe`：

1. 执行 `pip install -e ".[dev]"`；
2. 生成 SQLite 合成数据；
3. 执行 `npm install` 和 React production build。

如果只想安装后端：

```powershell
.\scripts\setup.ps1 -SkipFrontend
```

手工安装等价命令：

```powershell
conda activate langchain
Set-Location D:\ServicePilot
python -m pip install -e ".[dev]"
python -m servicepilot.seed
Set-Location .\frontend
npm install
npm run build
```

## 3. 启动开发环境

终端一，启动 FastAPI：

```powershell
Set-Location D:\ServicePilot
.\scripts\start-backend.ps1 -Reload
```

地址：

- API：`http://127.0.0.1:8000`
- Swagger：`http://127.0.0.1:8000/docs`
- 健康检查：`http://127.0.0.1:8000/api/health`

终端二，启动 React：

```powershell
Set-Location D:\ServicePilot
.\scripts\start-frontend.ps1
```

浏览器访问 `http://localhost:5173`。Vite 会把 `/api` 代理到 FastAPI。

如果已经执行过 `npm run build`，FastAPI 也会在 `http://127.0.0.1:8000/` 提供生产版静态页面。

## 4. 第一次演示

在左侧输入：

- 邮箱：`zhangwei@example.com`
- 订单：`SP-2026-0001`

推荐依次演示：

### 4.1 只读物流查询

```text
查询这个订单的物流状态
```

预期：Supervisor 调度订单和政策 Agent，返回状态与追踪号，不进入审批。

### 4.2 退款 HITL

```text
这个订单的充电器有问题，我想退款 299 元
```

预期：风险 Agent 命中“业务写入”和“超过 200 元”，工作流暂停。右侧显示订单、动作、风险原因和政策证据。
点击“批准并继续”后才会创建 `RF-...` 退款记录；点击“拒绝”不会写入退款表。

### 4.3 高风险投诉

```text
再不处理我就找律师并向监管部门投诉
```

预期：风险为 high，进入人工审批/升级路径。Agent 不承认法律责任，也不自动承诺赔偿。

### 4.4 隐私隔离

把邮箱改成 `customer002@example.com`，订单仍填写 `SP-2026-0001`，然后查询订单。

预期：只返回身份不匹配，不泄露订单是否存在、金额和商品明细。

## 5. Mock 与真实模型

默认 `.env.example` 中：

```dotenv
SERVICEPILOT_MODEL_MODE=mock
```

Mock 模式仍会完整运行数据库、RAG、Supervisor、审批、审计和评测，只把意图和回复语言部分替换为确定性代码。

启用 OpenAI 兼容接口：

```powershell
Copy-Item .env.example .env
```

编辑 `.env`：

```dotenv
SERVICEPILOT_MODEL_MODE=openai_compatible
SERVICEPILOT_MODEL_NAME=你的模型名
SERVICEPILOT_API_KEY=你的密钥
SERVICEPILOT_BASE_URL=https://你的服务商/v1
SERVICEPILOT_TEMPERATURE=0.1
```

重启后端。密钥只放在 `.env`，不要放进前端，因为浏览器中的变量无法保密。

模型需要较好地支持 JSON Schema/structured output。即使模型分类错误，高风险关键词硬规则仍只允许提高风险，
不会允许模型把已命中的 high 降级。

## 6. 命令行运行

只读示例：

```powershell
conda activate langchain
servicepilot-cli --message "查询这个订单的物流状态" `
  --email "zhangwei@example.com" --order-id "SP-2026-0001"
```

退款示例会在终端询问 `是否批准？[y/N]`：

```powershell
servicepilot-cli --message "我想退款 299 元" `
  --email "zhangwei@example.com" --order-id "SP-2026-0001"
```

自动化脚本不应误执行退款，可加 `--auto-reject`。

## 7. API 调用

创建工单：

```powershell
$body = @{
  message = "我想退款 299 元"
  customer_email = "zhangwei@example.com"
  order_id = "SP-2026-0001"
} | ConvertTo-Json

$result = Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:8000/api/v1/chat `
  -ContentType "application/json; charset=utf-8" `
  -Body $body
$result
```

响应为 `pending_approval` 时保存 `thread_id`，再提交审批：

```powershell
$decision = @{
  approved = $false
  reviewer = "manager-001"
  comment = "证据不足，暂不退款"
} | ConvertTo-Json

Invoke-RestMethod -Method Post `
  -Uri "http://127.0.0.1:8000/api/v1/approvals/$($result.thread_id)" `
  -ContentType "application/json; charset=utf-8" `
  -Body $decision
```

常用接口：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 服务、模型模式、数据表数量 |
| GET | `/api/v1/demo` | 演示账号 |
| GET | `/api/v1/config/public` | 非秘密业务参数 |
| POST | `/api/v1/chat` | 创建/继续客服会话 |
| POST | `/api/v1/approvals/{thread_id}` | 恢复人工审批 |
| GET | `/api/v1/tickets/{ticket_id}/audits` | 查看审计轨迹 |

## 9. Docker

```powershell
Set-Location D:\ServicePilot
docker compose up --build
```

访问 `http://localhost:8000`。Compose 使用命名卷保存业务数据库与 checkpoint。

使用真实模型时，先复制 `.env.example` 为 `.env` 并填写变量。不要把 `.env` 提交到 Git。

若出现 `docker.m.daocloud.io ... 401 Unauthorized`，这是 Docker Desktop 的 registry mirror 配置问题，
不是 Dockerfile 问题。打开 Docker Desktop 设置，移除或更新失效的 DaoCloud mirror，重启 Docker 后再构建。

无法立即修改 Docker Desktop 时，可临时使用微软官方开发基础镜像（体积明显更大）：

```powershell
$env:NODE_IMAGE="mcr.microsoft.com/devcontainers/javascript-node:24-bookworm"
$env:PYTHON_IMAGE="mcr.microsoft.com/devcontainers/python:1-3.13-bookworm"
docker compose up --build
```

本项目已使用这组替代镜像完成构建和健康检查。代理修复后建议清除变量，恢复轻量的 Node alpine/Python slim。

## 10. 重置数据

以下命令会清空本项目 SQLite 中的工单、退款和审计数据，并重建合成数据：

```powershell
python -m servicepilot.seed --force
```

只应对演示数据库使用，不要把 `--force` 指向真实数据库。

删除 checkpoint 会使待审批线程不可恢复。需要新演示环境时，关闭后端后再处理 `data/checkpoints.db`。

## 11. 常见问题

### 找不到 `servicepilot-api`

当前 Conda Scripts 目录可能不在 PATH。使用模块方式即可：

```powershell
& "$env:USERPROFILE\miniconda3\envs\langchain\python.exe" -m uvicorn servicepilot.api:app --port 8000
```

### 中文在终端显示问号

先执行：

```powershell
chcp 65001
$env:PYTHONUTF8="1"
```

Web UI 和 UTF-8 文件不受此问题影响。

### 修改政策后没有效果

当前 PolicyRetriever 在服务启动时加载文档。修改 Markdown 后重启 FastAPI。

### 调整参数后没有效果

`business_rules.json` 在进程中缓存。修改后重启服务，或在开发代码中调用 `reload_business_rules()`。

### 审批恢复返回冲突

必须使用产生暂停的同一个 `thread_id`。如果 checkpoint 文件被删除或服务配置到了另一个 checkpoint 路径，线程无法恢复。
