# ServicePilot 评测指南

## 1. 为什么不能只看“回答像不像”

售后 Agent 的关键错误往往不是文风，而是：

- 把退款识别成一般咨询；
- 该审批时直接写数据库；
- 邮箱不匹配却泄露订单；
- 引用了过期政策；
- 审批拒绝后仍声称退款完成。

因此当前离线评测优先覆盖业务行为，再考虑语言质量。

## 3. 指标定义

### Intent Accuracy

实际 `state.intent` 等于期望意图的比例。分类是后续路由的基础。

### Approval Routing Accuracy

是否出现 LangGraph interrupt 与 `expected_approval` 一致。该指标比“模型说需要审批”严格，因为它验证流程确实暂停。

### Privacy/Error Accuracy

缺少身份或身份不匹配时，标准化错误代码是否出现；正常样本不得出现错误。

### Evidence Recall@3

期望政策 ID 是否位于最多 3 条 evidence 中。它不评价排序的全部质量，但能快速发现关键政策丢失。

### Pass Rate

一个样本必须同时通过 intent、approval、error 和 evidence 才算通过。

## 4. 运行方式

```powershell
conda activate langchain
Set-Location D:\ServicePilot
python -m servicepilot.evaluation
```

评测遇到审批时会自动“拒绝”，避免测试执行退款副作用。报告：

- `reports/latest_eval.json`：逐条机器可读结果；
- `reports/latest_eval.md`：人工摘要。

当前 Mock 固定集结果：

| 指标 | 结果 |
|---|---:|
| 样本数 | 50 |
| Pass Rate | 100% |
| Intent Accuracy | 100% |
| Approval Accuracy | 100% |
| Privacy/Error Accuracy | 100% |
| Evidence Recall@3 | 100% |

这只能证明当前确定性规则对当前合成集合通过，不能写成“生产准确率 100%”。

## 5. 添加用例

建议每次修 bug 都增加一个回归样本。新增用例应包含：

- 正常表达；
- 口语、错别字、同义词；
- 多意图，例如“物流一直不更新，我要退款”；
- 对抗表达，例如要求忽略政策直接退款；
- 边界金额 199、200、201；
- 不同政策版本和地区；
- 高风险词正例与相似词反例。

修改后运行：

```powershell
python -m servicepilot.evaluation
python -m pytest
```

## 6. 防止评测集过拟合

当前 `policy_agent.py` 使用意图提示词提升小型本地 Embedding 的召回。这是可解释的领域增强，但不能不断针对单个测试句增加词。

建议拆分：

- `train/dev`：用于调规则和 Prompt；
- `test`：只有发布前运行；
- `challenge`：注入、歧义、多轮和长文本；
- `production shadow`：脱敏真实分布，由人工标注。

## 7. 真实模型评测

切换 OpenAI 兼容模型后，先保留同一批确定性指标，再增加：

- Schema 成功率；
- groundedness/事实一致性；
- 政策引用正确性；
- 回复完整性与礼貌；
- P50/P95 延迟；
- 每工单输入/输出 Token 与成本；
- 工具调用次数；
- 人工接管率。

不要让同一个模型既生成答案又做唯一裁判。高风险样本需要规则评测或人工复核。

## 8. LangSmith 可选增强

启用环境变量后，现有图会自动记录 traces。可以把 JSONL 上传为 Dataset，配置：

- trajectory evaluator：Agent 顺序和工具选择；
- LLM-as-judge：回复质量与证据一致性；
- human feedback：审批人对建议方案评分；
- online evaluation：线上抽样，不阻塞主请求。

LangSmith 是可选增强，本地 `evaluation.py` 永远应能在没有账号和网络时运行。

| 门槛 | 示例目标 |
