# 从 MVP 到真实企业上线：差距清单

当前 ServicePilot 是 production-shaped MVP：结构接近企业项目，但使用合成数据和简化基础设施。以下事项没有完成前，不应接真实退款。

## P0：上线阻断项

- [ ] OAuth/OIDC/企业 SSO；
- [ ] 客户身份二次验证，不依赖手填邮箱；
- [ ] 审批人身份来自认证上下文，不来自 request body；
- [ ] RBAC 与金额审批权限；
- [ ] Postgres 业务库与迁移工具；
- [ ] Postgres LangGraph checkpointer；
- [ ] 退款幂等键和支付网关沙箱；
- [ ] 密钥管理器，不用本地 `.env`；
- [ ] PII 分类、脱敏、保留周期和删除流程；
- [ ] 法务、安全、隐私和财务评审；
- [ ] 高风险红队与越权测试；
- [ ] 灾备、备份和恢复演练。

## P1：可靠性与可观测

- [ ] OpenTelemetry traces/metrics/logs；
- [ ] P50/P95/P99、错误率、审批积压和退款失败告警；
- [ ] 模型 timeout、fallback、熔断和限流；
- [ ] 外部 API 重试和“不确定结果”处理；
- [ ] Outbox/消息队列处理长时间业务动作；
- [ ] 审计日志防篡改与访问控制；
- [ ] 多实例负载和故障转移测试；
- [ ] SLO、on-call 和事故响应手册。

## P1：RAG 与内容治理

- [ ] 文档所有者、审批人和发布流程；
- [ ] 长文档 chunking 和 parent-child 引用；
- [ ] 企业 Embedding 与 pgvector；
- [ ] 文档 ACL/租户隔离；
- [ ] 文档注入扫描；
- [ ] 版本回滚和生效时区；
- [ ] 无证据/冲突政策告警；
- [ ] 定期离线与线上评测。

## P2：产品闭环

- [ ] 人工工作台队列、分配、SLA 和升级；
- [ ] 客服编辑建议后再发送；
- [ ] 客户满意度与解决率；
- [ ] 失败原因标签和内容运营看板；
- [ ] 成本、Token 和接管率分析；
- [ ] 灰度开关与 A/B；
- [ ] 多语言和无障碍；
- [ ] 用户申诉和错误纠正流程。

## 威胁模型摘要

| 威胁 | 当前缓解 | 仍需生产措施 |
|---|---|---|
| Prompt Injection | LLM 无任意 SQL/代码权限，白名单动作 | 文档隔离、红队、模型网关 |
| 订单枚举 | 邮箱+订单联合查询、统一错误 | 强身份认证、速率限制 |
| 未授权退款 | HITL、确定性规则 | RBAC、双人审批、支付幂等 |
| 过期政策 | active/effective date 过滤 | 文档发布治理、时区和回滚 |
| 重放重复执行 | 审批顺序与事务 | 全局幂等键、唯一约束、outbox |
| 秘密泄露 | `.env` 忽略、前端不含 Key | Vault/KMS、密钥轮换、DLP |
| 审计篡改 | 独立审计表 | WORM/签名日志/SIEM |

## 现实的上线顺序

1. 只读“查订单/查政策”建议模式；
2. 客服确认后发送回复，不自动写业务系统；
3. 接入低风险工单创建；
4. 退款只生成草稿，由现有后台审批；
5. 小额、低风险、强幂等场景有限自动化；
6. 持续评测和事故复盘后再扩大范围。

这比一开始追求全自动更符合企业风险管理。
