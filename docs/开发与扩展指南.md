# ServicePilot 开发与扩展指南

## 1. 开发前检查

```powershell
Set-Location D:\ServicePilot
git status
.\scripts\run-checks.ps1
```

建议每个功能同时修改：实现、测试、评测样本、对应文档。

## 2. 新增一个专业 Agent

以发票 Agent 为例：

1. 在 `schemas.py` 增加 `invoice` intent 和需要的状态字段；
2. 新建 `agents/invoice_agent.py`，只返回结构化结果；
3. 在 `agents/__init__.py` 导出工厂；
4. 在 `workflow.py` 注册节点；
5. 在 Supervisor 的路由规则里定义何时调用；
6. 在 `completed_agents` 和轨迹中使用唯一名称；
7. 增加单元测试和 JSONL 评测；
8. 更新架构文档。

不要让新 Agent 随意读取所有表或执行任意代码。先定义最小工具权限。

## 3. 新增数据库工具

在 `database.py`：

- 参数始终使用 `?`；
- 返回字典而不是 sqlite Row；
- 查询中加入客户归属/租户隔离；
- 写操作用事务；
- 对重复请求增加唯一约束或幂等键；
- 不把异常堆栈直接回给客户。

对应测试至少包含正常、找不到、越权和恶意输入。

## 4. 新增业务动作

流程：

1. Resolution Agent 产生白名单类型，如 `grant_coupon`；
2. Risk Agent 明确审批条件；
3. Approval payload 展示完整上下文；
4. Action Agent 实现唯一执行入口；
5. 数据库记录动作结果；
6. Response Agent 只根据 `action_result` 声明成功；
7. 增加拒绝零副作用、批准一次和重复恢复测试。

禁止根据 LLM 的自然语言字符串动态导入函数或 eval。

## 5. 新增/升级政策

参照 `参数调试指南.md` 的元数据规范。文档内容不要混入 Prompt 指令；Retriever 返回的政策属于不可信外部内容，
真实系统应防止文档注入，例如把“忽略系统提示”作为政策文本执行。

每次政策升级保留历史版本，测试 inactive 版本不进入 evidence。

## 6. 替换 Embedding

实现 LangChain `Embeddings` 接口，然后在 `PolicyRetriever` 构造函数注入。建议对比：

- 本地 BGE-small-zh；
- BGE-M3；
- OpenAI 兼容 Embedding；
- 企业内部 Embedding API。

在同一 test split 上记录 Recall@3、延迟、内存和成本。生产向量库可以替换为 pgvector，但保留 Evidence 数据结构。

## 7. 接入真实订单系统

不要直接把 `database.py` 替换成一堆 HTTP 请求。定义接口：

```python
class OrderRepository(Protocol):
    def get_order_for_customer(self, order_id: str, identity: VerifiedIdentity) -> Order | None: ...
```

然后实现：

- `SQLiteOrderRepository`：本地；
- `RestOrderRepository`：客户 API；
- `MockOrderRepository`：测试。

真实 API 还需要超时、重试、熔断、认证、速率限制和字段脱敏。

## 8. 接入真实支付/退款

必须具备：

- idempotency key；
- 请求/响应审计但不记录卡号；
- 支付状态查询和对账；
- 网络超时后的“不确定状态”处理；
- 最小权限服务账号；
- 双人审批或金额分级；
- outbox/事件通知。

在这些条件完成前，Action Agent 只应生成退款申请，不调用真实支付。

## 9. 增加认证与 RBAC

建议角色：

- customer：只能提交自己的请求；
- support_agent：读取已分配工单；
- approver：批准一定金额范围；
- risk_manager：处理 high 风险；
- auditor：只读审计。

审批人不能由请求 body 任意声称。当前 `reviewer` 文本只为合成演示；生产必须从 JWT/SSO claims 获取。

## 10. 前端开发

```powershell
Set-Location D:\ServicePilot\frontend
npm run dev
npm run build
```

API 类型集中在 `src/api.ts`。如果后端模型改变，先修改类型再让 TypeScript 编译暴露受影响组件。

生产可从 FastAPI OpenAPI 生成 TypeScript client，减少手工漂移。

## 11. CI

`.github/workflows/ci.yml` 在无 API Key 的 Mock 模式执行：

1. Python 安装；
2. React 构建；
3. pytest；
4. 50 条离线评测；
5. Docker build。

真实模型评测不要对每个普通 PR 强制运行，可设为手动/夜间任务并使用受保护 Secrets。

## 12. 代码评审清单

- 是否扩大了 Agent 权限？
- 是否增加未经审批的副作用？
- SQL 是否参数化并包含租户/归属条件？
- checkpoint 重放是否会重复执行动作？
- 是否引用当前生效政策？
- 日志是否含 API Key/验证码/敏感个人数据？
- 是否增加失败路径测试？
- Mock 模式是否仍可离线运行？
- 文档和配置是否同步？
